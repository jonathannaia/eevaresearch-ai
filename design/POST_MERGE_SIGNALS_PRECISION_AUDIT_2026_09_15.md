## 2. Exemption / bypass / default-publish inventory (exact, current)

Every path that can let an item appear **without both correct subject attribution and concrete event evidence**:

1. **Lane A has no admission gate at all** (`daily_news_pipeline.py`) — every fetched, deduped, fresh item from a tracked company's own official feed is unconditionally published. Materiality is computed but never gates inclusion. This is a bypass by **lane**, not content shape.
2. **NIST source bypass** (`_NIST_SOURCE_ID`, `editorial_pipeline.py`) — never calls `assess_admission()`; admitted purely by `_matches_nist_allow_list()`, a fixed CHIPS/semiconductor keyword allow-list checked against title/summary alone, with no subject-attribution or anchor-evidence requirement beyond the allow-list terms themselves appearing.
3. **Space Force precondition exemption** (`_SPACEFORCE_SOURCE_ID`) — post-PR #61, exempted only from the fail-closed company/theme precondition; every item is now routed through `assess_admission()`. This closed the *unconditional* bypass, but the item remains fully exposed to bypass #4 below.
4. **Bare theme-only admission path** (`assess_admission()`'s final `if matched_themes: return AdmissionDecision(True, ...)`) — applies to **every** Lane B source, not source-specific. Any item with at least one theme-keyword phrase anywhere in title/summary and no company match is admitted with **zero** anchor/event-evidence requirement, unless the item is also personnel/consumer-format/law-firm shaped.
5. **Company-identified default admission path** (`if matched_companies: if identified_companies: return True`) — admits any company whose identity is established with zero anchor/materiality requirement, unless personnel/consumer-format/law-firm shaped. Identity for 105 of 115 tracked companies (every one not in the 10-company `_AMBIGUOUS_ALIAS_COMPANIES` list) requires only **title placement**, no action-language evidence at all.
6. **Gate D — `credible_editorial_reporting`** (materiality, `is_independent_news` sources only) — reaches HIGH_SIGNAL from a curated reporting-verb phrase + a length threshold + **any** taxonomy/anchor keyword appearing **anywhere** in the whole combined text. The PR #61 sentence-locality fix was applied only to Gate C; Gate D still uses the original, unbounded whole-document `taxonomy_hits`/`anchor_hits`.
7. **Watchlist `on_taxonomy_no_anchor` fallback** — any admitted item containing a taxonomy phrase anywhere in the whole text defaults to WATCHLIST (visible on the Dashboard by default, not hidden), with zero anchor evidence and zero HIGH_SIGNAL gate hit. Deliberately left global/unchanged by PR #61.
8. **Dashboard company-attribution display** (`src/ui/components/editorial_coverage.py::_tag_chips_html`) — renders `EditorialStory.matched_companies` (the raw, whole-text alias-match tuple) as-is; never filtered to the admission-validated `identified_companies` subset, which is computed inside `assess_admission()` and discarded (never persisted).
9. **Background is not a true suppression state** — it is an `st.expander`, one click from visible; several "reject or Background" fixtures above would still be discoverable there rather than truly absent.

No exemption above is company-specific, source-specific beyond what is documented (NIST/Space Force), or a bare keyword ban — each is a structural gap in the general admission/materiality architecture.

## 4. Proposed "concrete-event admission floor"

```
reject by default unless:
  correctly attributed subject
    (identified via title placement + action language for the 10 ambiguous-alias
     companies; title placement OR action language for every other tracked company —
     this pass does not propose narrowing that OR to AND universally, since doing so
     would weaken already-tested, correct coverage for genuinely subject-led headlines;
     see the prioritized plan below for the narrower, targeted alternative)
  AND a new, attributable concrete event
    (locally co-occurring with the subject/theme — same sentence or one of two
     adjacent sentences, reusing the existing _taxonomy_anchor_local_hits() shape —
     never "present anywhere in the document")
  AND a material economic, operational, contractual, capacity, regulatory, or
  program consequence
    (an existing hard gate — A/A2/A4/B/B2 — or a locally-anchored Gate C/D hit)
```

Tier mapping (no new tier introduced — see below):

- **Reject** (never admitted, never appears, not even in Background): no correctly-attributed subject at all, OR personnel/consumer-format/law-firm/event-invite/speech-format shaped with no anchor rescue.
- **Background** (admitted, hidden behind the expander): correctly attributed subject, but no concrete new event/consequence evidence anywhere near it.
- **Watchlist** (admitted, visible): correctly attributed subject AND a locally co-occurring but unquantified development (today's Gate C shape, extended to gate general visibility, not merely HIGH_SIGNAL).
- **High Signal**: correctly attributed subject AND a quantified/hard-evidenced consequence (existing Gates A/A2/A4/B/B2, or a locally-scoped Gate C/D).

**No "Review needed" tier exists in the current implementation** (confirmed in the prior Signals policy audit and unchanged by PR #61 — `NewsMaterialityTier` has exactly `HIGH_SIGNAL`/`WATCHLIST`/`BACKGROUND`). Introducing a fourth tier is a model/UI change beyond a minimal admission-floor patch; this audit recommends reusing **Background** as the de facto "hold for review" bucket rather than adding a new tier in the same pass. Internal admission/materiality reason strings (`personnel_announcement:...`, `theme_subject:...`, `credible_editorial_reporting:...`, etc.) are already never rendered on a user-facing card (confirmed by reading every `st.markdown`/card-rendering call site in `src/ui/components/editorial_coverage.py` and `src/ui/pages/daily_news.py` — only `materiality_tier` drives the visible section, never `materiality_reasons`) — this floor proposal preserves that separation.

## 5. Three highest-priority gaps

1. **Gate D and the Watchlist `on_taxonomy_no_anchor` fallback both use global, whole-document taxonomy/anchor matching instead of the sentence-local pairing PR #61 already built for Gate C.** This is the single most reusable fix — `_taxonomy_anchor_local_hits()` already exists — and plausibly explains 3 of the 5 fixtures (remarks, acquisition-culture commentary, Dreamforce discussion) reaching Watchlist/High Signal.
2. **Non-ambiguous companies (105 of 115 tracked companies, including Microsoft and NVIDIA) are identified as a story's "subject" by title placement alone**, with no requirement the company do anything. This is what lets a bare event-invite or conference-appearance headline pass admission purely from naming a company, and is distinct from (and prior to) the materiality-tier question.
3. **`EditorialStory.matched_companies` — the raw, whole-text company-mention tuple — is persisted and displayed as-is, never filtered to the admission-validated `identified_companies` subset.** A company that is merely co-mentioned (e.g., NVIDIA in a Microsoft event story) is shown as an equal "Companies shown" chip; this is a genuine attribution-display defect, independent of the admission decision itself.
